# 批量回归规则

案例日期固定在2026-11-01这一评估背景：正常案例为11月10日起，远期天气为2027年6月；预期没有可确认的逐日预报。若在其他日期重跑，须检查天气预期是否仍成立，并生成新的结果文件，不能静默复用旧结果。

## 判定

- 1至11：必须为valid_plan，并独立重跑结构、城市、日期及显式请求约束校验，不能以“能解析JSON”代替。
- 5：预算不得超过1000元；价格是否合理和是否明确为估算仍需复核。
- 6：必须包含指定博物馆，当前名称按精确匹配，预约及开放时间需复核。
- 8：交通类型必须明确为公共交通或步行；真实路线是否遵守仍需复核。
- 9：每天最多2个景点。
- 12至14：必须返回澄清/冲突说明，并在澄清前不调用工具。关键词只检查最低内容，不是语义正确性的充分条件。
- 15：返回天气文本，实际执行工具，并包含北京；内容真实性需与工具结果核对。

亲子适宜性、老人步行强度、住宿位置、饮食与开放时间等不靠关键词假装验证。规则通过但存在此类检查的案例标记manual_review，不计为完整pass。

## 命令

```powershell
.\.venv\Scripts\python.exe evals/run.py --ids all --output .work/batch.json --timeout 190
# 中断后只运行缺少的案例，不覆盖已完成的失败；源文件或案例变化会拒绝续跑
.\.venv\Scripts\python.exe evals/run.py --ids all --output .work/batch.json --resume
.\.venv\Scripts\python.exe evals/report.py .work/batch.json docs/批量回归结果.md
```

每条完成后保存结果、运行报告、规则判定及失败原因。修复后复测用新的文件，保留修复前结果。报告生成器不发布原始请求和模型回答；它不会自动完成人工复核。

## 单/多架构配对

`python evals/paired.py`默认选择1、3、5、6、8、14、15共7例，两架构顺序交替执行，共14次任务。`--rounds`可指定1至3轮，`--resume`从同一源码与设置的文件继续。默认输出`.work/paired-architectures.json`。

两架构共享全部校验、修正、模型及预算，所有子模型调用累计计数；委派不是外部网络请求。默认用户入口仍为单Agent，评估完成前不宣称哪种更好。
