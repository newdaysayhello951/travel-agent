# 共性框架验证

本轮只完善单次规划的共用底座，不做单/多Agent性能比较，也不接数据库。

## 验证范围

- 30项自动测试通过：字段级诊断、预算重算、修正成功/耗尽、超时、取消、工具及模型预算、并发隔离、缓存、流式草稿隔离、返程日和事实保护等。
- Streamlit AppTest初始加载与载入真实有效行程的结果页均无异常，CLI渲染成功；这不等于完整浏览器视觉或真实提交交互验收。
- 真实流式天气查询完成，7.66秒、2次模型调用、1次工具尝试，状态为text而非行程成功。
- 合成错误草稿通过真实模型一次修正，将总额0修正为310，18.44秒。首次Agent输出是测试桩，不代表真实完整旅行规划测试。
- 最终版本真实长沙三日规划通过明确请求约束及结构/预算校验：90.37秒，10次模型调用，21次工具尝试、3次缓存命中，供应方上报114510 tokens。Python将餐饮小计570重算为455、总额1730重算为1615；未修改每日明细，不需要模型修正。
- 上述最终结果只代表一个案例通过，不代表路线可执行性或整体成功率已验证。

## 排查中发现的问题

1. 重复查询耗尽工具预算：补单次运行高德只读缓存及工具调用节制要求，不跨请求缓存天气。
2. 非JSON输出和餐饮汇总错误：补完整代码块提取和字段错误；汇总改为Python确定性重算，所有调整记录前后值。
3. 路线失败时返回普通说明：区分text和valid_plan，明确约束的请求必须得到合格行程；允许有依据的部分资料降级，不编造路线详情。
4. 离店日null住宿及空景点被误拒绝：修正最后一天语义，并同步页面/CLI/导出兼容。
5. 模型修正时改动地址、坐标和明细数量：增加已有事实保护，拒绝为了通过校验而重新编造明细。

上述问题来自本轮不同版本的真实运行，不作为架构优劣结论。

## 未覆盖的边界

- 未批量重复执行全部15条案例，不能宣称总体稳定率或性能优势。
- 缺少开放时间、交通冲突、实时价格真实性的完整校验。
- 无法解析原始草稿时不能进行完整字段事实对比；自动修正可能仍失败，默认最多一次。
- 已成功的“结构与预算一致”不等于实际路线、报价或可预订性已验证。
