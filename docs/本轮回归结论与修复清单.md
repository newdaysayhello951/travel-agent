# 本轮回归结论与修复清单

## 执行结果

- 48项自动测试通过，包括真实LangChain图与确定性模型/网络替身的组合测试。
- 首轮真实15例已全部完成，12条通过自动规则，3条失败；其中11条仍需人工复核，1条只通过已定义的自动规则。详见《首轮十五例回归结果》。
- 首轮失败为案例1（模型循环至调用上限）、8（工具预算耗尽）、14（缺目的地却开始查询）。
- 修复后对1、7、8、12、13、14、15定向复测；中间发现前置提取缺intent字段，修正提示后再次复测12至15。最新各次结果均通过自动规则，见《修复后定向复测汇总》。
- 这些复测来自两批开发快照，不能宣称最终代码同一版本全量15/15通过，更不能由单次结果判断稳定率或架构优劣。

## 实际修复

| 问题 | 修复方式 | 验证依据 |
|---|---|---|
| 缓存命中仍发生模型循环 | 重复查询或临近调用预算时撤下工具，保留整理与修正空间 | 中间件/真实图集成测试；真实低预算天气测试触发finalization_forced=true |
| 工具并行批次耗尽预算直接中断 | 超限调用不发网络请求，返回停止查询提示，随后受控收尾 | 组合故障测试通过，实际请求上限不提高 |
| 交通类型缺失 | 从明确交通文本映射标准类型，含冲突则拒绝，不靠改标签掩盖驾车 | 公交案例复测通过，仍需实际路线复核 |
| 修正一个字段却改变酒店等事实 | 白名单字段补丁；整份JSON响应也只提取允许字段 | 真实模型修正注入的day_index错误成功，1次模型调用、无地图查询；替身首次输出并非真实完整规划 |
| 缺目的地时擅自查询 | 无工具前置提取，城市须在原文有依据；缺失/冲突先追问 | 案例12、13、14复测均0工具调用；提取失败也保持0工具调用并给字段诊断 |
| 提取及补丁响应不兼容 | 用明确JSON数据实例替代容易被模型误解的Schema提示，兼容白名单内的JSON Pointer路径 | 真实提取四例通过、真实字段补丁通过 |
| 费用未说明为估算 | 程序补估算标识，记录normalizations，不改明细 | 确定性回放和自动测试通过 |
| 返程日重复收住宿费 | 结构化请求默认最后一天不续住，显式stay_on_last_day=true可例外 | 规则测试通过，南京案例复测通过 |

## 事实与业务边界

规则通过只说明满足已定义条件。亲子强度、老人步行、地点真实性、开放时间、预约和实际价格仍不能全部自动判定；文本复核发现的问题见《批量回归人工复核说明》。

下一步在同一已提交版本重复全量回归，并补工具来源证据和人工标签，再考虑单/多Agent比较。本轮没有接数据库或改变为多Agent。
