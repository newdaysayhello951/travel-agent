# 持久化与多轮行程修改

页面启动后自动创建`.data/travel-agent.db`，保存会话、每个通过校验的行程版本、当时的结构化约束、对话和执行报告。重启页面可从侧栏加载历史版本。数据库与个人旅行记录不提交Git。

新增行程与继续修改均经过原有模型/工具预算、字段校验及有限修正。修改提示携带原始需求、当前有效行程、最近10次成功修改要求与本次要求，不拼接所有旧版本。硬约束沿用上一版本；需要调整预算、日期、必去景点等时显式更新`TripRequest`字段。未知字段拒绝，不能用拼写错误绕过约束。长期重要的硬约束应写入结构化请求，不依赖有限长度的自然语言历史。

页面提供预算修改和保留酒店选项。勾选后，对已有酒店的名称、地址、坐标和报价再做确定性比较；不符合则保存失败报告，不产生新行程版本。这里保留的是原有报价信息，不表示价格已经实时核验或完成预订。

每次成功修改追加版本，历史版本不可通过修改接口覆盖。事务同时写入版本、消息和运行报告；`expected_version`乐观锁阻止并发覆盖。查看旧版本后直接修改会要求先加载最新版本，不自动把旧版本覆盖到最新版本。

生成失败、超时或取消时记录失败，不替换上一个有效行程。数据库本身不可用时无法保证保存失败记录；日志仅记录执行编号，不输出SQL参数、凭据或原始异常。

## 命令行

原`Agent.py`保留即时问答入口；需要持久化时使用：

```powershell
.\.venv\Scripts\python.exe travel_cli.py create "长沙两日游，喜欢历史文化" --city 长沙 --start 2026-11-10 --end 2026-11-11 --budget 1800
.\.venv\Scripts\python.exe travel_cli.py list
.\.venv\Scripts\python.exe travel_cli.py show <会话ID> --version 1
.\.venv\Scripts\python.exe travel_cli.py revise <会话ID> "第二天减少景点，轻松一些" --expected-version 1 --keep-hotels
.\.venv\Scripts\python.exe travel_cli.py history <会话ID>
```

`revise --updates`接受JSON对象，字段与`TripRequest`一致。例如`{"budget_limit":1500}`，或用`null`取消预算上限。命令行传JSON的转义方式取决于终端；Python调用可直接传字典。页面修改框的明确预算设置优先于自然语言描述，不自动提取所有修改要求为硬约束。

## 数据库边界

本地默认SQLite，无需额外启动数据库进程。ORM使用SQLAlchemy通用JSON与事务模型；可通过`.env`的`DATABASE_URL`改为`postgresql+psycopg://...`，另安装`psycopg[binary]`并准备独立数据库。本次本机没有配置可用的PostgreSQL服务，不能宣称真实PostgreSQL连接已验证。

当前为初始建表，使用`metadata.create_all`，尚未提供Alembic升级迁移；现有表不会被自动删改。尚无多用户身份认证与数据隔离，页面适合个人本地使用。FastAPI与RAG尚未实现。
