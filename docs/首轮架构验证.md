## 发现

- 旧版为超过当前预报范围的旅行日期填充了天气，属于事实依据问题。
- 新版同案例 weather_info 为空，遵循本轮新增的“不得编造远期天气”提示词要求；这不代表其他业务约束已经全部满足。
- 最初两次运行的 callback 绑定没有采集到调用数及 token，记录中的 0 是缺失值，不能视为无调用或零成本。
- 已修正 callback 为工作流级绑定；天气案例采集到 2 次模型调用、供应方上报 5162 tokens。后续缺失指标记为 null。
- 新脚本额外记录源文件哈希，避免未提交工作区只记录 HEAD 造成版本歧义。

## 本地环境

在普通执行环境中模型及 MCP 依赖成功导入，无须重装。之前 SSL / pywin32 导入失败及本地代理拒绝连接发生于受限执行环境，不能当作真实服务故障。

## 后续评估

对相同模型和需求重复执行，统计质量、耗时分布和调用量。日期冲突、缺目的地、预算冲突等案例需要人工标注期望行为；当前 parsed_plan 只说明能否解析，不等同于通过业务评估。外部工具超时故障注入和系统性业务校验留待下一轮。
